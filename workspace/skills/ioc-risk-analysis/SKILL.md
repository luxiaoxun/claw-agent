# IOC Risk Analysis Skill

## 目标

本 Skill 用于分析用户提供的威胁情报 IOC（如域名、URL、IP 或文件 HASH），自动评估其潜在安全性风险，并按照固定模板生成结构化的安全分析报告。

## 适用场景

- 用户希望判断某个网站、链接或 IP 是否安全
- 用户怀疑某个 URL 是钓鱼链接或恶意站点
- 用户需要一份标准化的网站或域名安全分析报告

## 使用约束

- 如果IOC对象是URL，**必须使用 `web_fetch` 工具**获取目标 URL 的页面内容，禁止凭经验或猜测填写内容分析部分。
- 如果 `web_fetch` 获取失败，需在报告中明确说明失败原因，并仅基于 URL 特征进行最小化风险推断。
- 报告必须严格遵循输出模板，语言简洁、结论明确。
- **禁止**建议用户在可疑页面上输入密码、个人信息或执行敏感操作。

## 分析流程

### 第一步：获取页面内容

调用 `web_fetch` 工具，传入用户提供的完整 URL。成功时提取页面标题、主要文本内容、表单特征等；失败时记录错误信息。

### 第二步：多维风险分析

基于 URL 特征和获取到的页面内容（如有），从以下四个维度进行评估：

1. **域名可疑性**
   - 是否为随机字符组合、异常长的域名或非常见顶级后缀（如 `.xyz`, `.top`）
   - 是否使用 `login`、`secure`、`webview`、`account` 等钓鱼常用子域名

2. **URL 参数风险**
   - 是否包含长随机 token、可疑重定向参数或编码内容

3. **页面内容分析（仅当获取成功时）**
   - 是否要求输入密码、私钥、身份证号、银行卡等敏感信息
   - 是否存在乱码、伪造品牌、邮箱拼写错误、非正规中文/英文表达
   - 是否使用“账号异常”、“验证身份”、“安全升级”等社会工程学术语

4. **技术特征（中性记录）**
   - 是否启用 HTTPS（不视为安全保证）
   - 是否使用 Cloudflare、CDN、隐藏真实 IP 等服务

### 第三步：综合判定风险等级

根据上述分析，判定以下等级之一：

- **高风险**：明确存在钓鱼、欺诈或恶意特征
- **中风险**：存在可疑特征但无明确恶意证据
- **低风险**：无明显异常特征

### 第四步：生成报告

按照以下固定模板输出完整报告。
